# Wave 5 — hardening and polish (2026-08-27, after waves 1–4)

Same rules as README.md. Four streams, disjoint areas.

## Stream: sandbox-uid (security)
Areas: `packages/harness` (`src/job/worker.ts`, `exec.ts`), `apps/job/Dockerfile`, `packages/resident`
(only where it spawns workers), `docs/M3-REVIEW.md` (#18 follow-up note), `TODO-EXTERNAL.md`.
- Worker sessions (Agent SDK subprocess and every command it runs) must run under a second
  unprivileged uid (`worker`, uid 1001) so a model-driven shell cannot read the job process's
  memory/`/proc` or the ECS task-role credential endpoint response cached by the job. The job
  (uid `node`) owns `/work`; the worktree for a task is `chown`ed to `worker` before the session
  starts and back after (or use group-writable dirs with `setgid`). Implement via `spawn` option
  `uid`/`gid` (needs the job to start as root and drop privileges — prefer `su-exec`/`setpriv` in
  the image with `CAP_SETUID` only at start; document the choice). Make it configurable
  (`WORKER_UID`, default: same uid → current behaviour) so `npm run job:dev` keeps working.
- Block the ECS credential endpoint from workers regardless of uid: the proxy sidecar is not
  involved (169.254.170.2 is in NO_PROXY) — add an `iptables`-free mitigation: unset
  `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` (already stripped by `sandboxEnv`) AND verify with a
  test that `sandboxEnv` strips every `AWS_*`/`ECS_*` key; add a worker system-prompt line that
  network calls other than npm/GitHub/Anthropic fail.
- Tests with fakes for the uid switch logic; a docker-compose `--profile job` run that proves a
  worker cannot read `/proc/<job pid>/environ` — describe the manual check in `apps/job/README.md`.

## Stream: licence-gate (M4 extra)
Areas: `packages/harness` (`src/job/gates/licence.ts` new + registration in the gate order after
review), `packages/models` (gate name enum), `legal/kundavtal.md` §third-party licences reference
only, tests.
- A deterministic gate (no model call): run `npm ls --all --json` in the customer repo, collect
  every package licence (from `node_modules/<pkg>/package.json`), fail on a denylist (GPL-2.0-only,
  GPL-3.0-only, AGPL-*, SSPL-*, unknown/UNLICENSED for non-private packages) unless waived via
  `gateWaivers` (`licence:<pkg>@<version>`), and write `THIRD-PARTY-LICENCES.md` into the repo
  (package, version, licence, repository) so delivery includes it (M5 handover lists it).
- Gate report includes counts by licence and the offending packages.
